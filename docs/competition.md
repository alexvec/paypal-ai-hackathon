## Platform facts relevant to the build (PayPal docs, opened)

These are not hackathon rules.

- Sandbox needs a PayPal login (existing or new) on the Developer site; the account must be enabled via the verification email. A business account is not mentioned as required for the sandbox. https://developer.paypal.com/api/rest/sandbox/
- Client ID and secret: Developer Dashboard, Apps & Credentials, Default Application or Create App. New developer accounts include a personal and a business sandbox account (Testing Tools, Sandbox Accounts). A PayPal Business account is needed to go live. Token endpoint on the sandbox host is api-m.sandbox.paypal.com, path /v1/oauth2/token, client_credentials. https://developer.paypal.com/api/rest/
- Orders API endpoints and workflow were not explained on the pages opened: UNVERIFIED here. Use https://developer.paypal.com/api/rest/ and the Orders reference when building.
- Agent toolkit, MCP server (@paypal/mcp, remote endpoint mcp.paypal.com), and Agent Ready / Agentic Commerce Protocol exist per search-result snippets only (not opened pages): https://developer.paypal.com/ai-tools/agent-tools, https://developer.paypal.com/agent-ready/agentic-commerce-protocol, https://developer.paypal.com/community/blog/paypal-model-context-protocol/. The quickstart URLs I tried (https://developer.paypal.com/tools/agents/quickstart/ and https://developer.paypal.com/docsai/tools/agent-toolkit-quickstart) returned 404, so package names, auth and versions need checking before the build relies on them. The snippet says the agentic checkout flow names Braintree as the payment provider, so sandbox support for it is unconfirmed.
